# 05 — EC2

## What is EC2?

EC2 stands for **Elastic Compute Cloud**.

It provides virtual compute instances that you can configure and run in AWS.

> Source correction: one of the uploaded 100xDevs slides expands EC2 as "Elastic compute Version 2". The correct expansion is **Elastic Compute Cloud**.

## EC2 mental model

```text
EC2 Instance
 |
 +-- AMI -> operating system/image
 +-- Instance Type -> CPU/RAM characteristics
 +-- EBS -> disk
 +-- Security Group -> network firewall
 +-- IAM Role -> AWS permissions
 +-- Key pair -> SSH authentication
```

## AMI

Amazon Machine Image.

A template used to launch an instance.

Examples include Linux/Ubuntu/Windows images.

## Instance type

Defines the compute characteristics.

Think:

```text
CPU
Memory
Network
Storage characteristics
```

Choose according to workload.

## Key pair

Used for secure access to an instance in common SSH workflows.

Example:

```bash
chmod 400 my-key.pem
ssh -i my-key.pem ubuntu@<public-ip>
```

The exact username depends on the OS image.

## Launching an EC2 instance

Typical workflow:

1. Choose AMI.
2. Choose instance type.
3. Configure networking.
4. Configure storage.
5. Configure security group.
6. Configure key pair if needed.
7. Launch.
8. Connect.
9. Install/deploy application.

## Deploying a Node.js backend

Example:

```bash
git clone <repository>
cd app
npm install
node index.js
```

For production, use a proper process manager/container/orchestrator rather than relying on a foreground development command.

## Public IP

An EC2 instance can have a public IPv4 address depending on configuration.

Be careful: public IP exposure is not the same thing as application security.

## Elastic IP

A static public IPv4 address that can be associated with AWS resources under supported configurations.

Use deliberately; architecture using a load balancer and DNS often avoids depending directly on a single server IP.

## EC2 lifecycle

Common states include:

```text
pending -> running -> stopping -> stopped
                     |
                     -> terminated
```

Stopping is not the same as terminating.

## EC2 deployment architecture

Simple:

```text
Client
  |
Public IP
  |
Security Group
  |
EC2
  |
Node.js
```

More production-oriented:

```text
Client
  |
ALB
  |
EC2 instances
  |
Application
```

## Important operational point

EC2 is infrastructure you operate.

You may be responsible for:

- OS updates
- Runtime
- Process management
- Logs
- Security
- Deployment
- Scaling
- Monitoring

That operational burden is why managed services and containers exist.
