# 08 — S3

## What is S3?

Amazon Simple Storage Service (S3) is object storage.

It is commonly used for:

- Images
- Videos
- PDFs
- Backups
- Logs
- Static assets
- Build artifacts

## Bucket

A bucket is a logical container for objects.

Example:

```text
my-app-assets/
 |
 +-- images/
 |    +-- logo.png
 |    +-- avatar.jpg
 |
 +-- documents/
 |
 +-- builds/
```

## Object

An S3 object has data plus metadata and is identified within a bucket by a key.

Example key:

```text
users/123/profile.jpg
```

The "folder" structure is primarily a key naming convention rather than a traditional filesystem hierarchy.

## Versioning

S3 Versioning can preserve multiple versions of objects.

Useful for:

- Recovery
- Accidental deletion protection
- Change tracking

## Lifecycle rules

Automatically transition or expire objects based on rules.

Example:

```text
New object
   |
S3 Standard
   |
older
   |
lower-cost storage class
   |
archive/delete according to policy
```

## Access control

S3 access can involve:

- IAM policies
- Bucket policies
- Object ownership/access settings
- Block Public Access
- CloudFront Origin Access Control

Do not make buckets public by default.

## Static website deployment

For a static React build:

```bash
npm run build
```

Then upload the generated build output to S3.

The uploaded 100xDevs frontend material specifically demonstrates uploading the React `dist` bundle to S3.

## S3 + CloudFront

Preferred architecture for a static frontend:

```text
User
 |
CloudFront
 |
S3
```

S3 stores the files.

CloudFront distributes them.

## Presigned URLs

A presigned URL gives temporary access to an S3 object without making the object publicly accessible.

Typical upload flow:

```text
Client
  |
Backend asks S3 for presigned upload
  |
Presigned URL
  |
Client uploads directly to S3
```

This avoids sending large files through your application server.

## S3 consistency

Modern S3 provides strong read-after-write consistency for object operations. You should still design applications around correct error handling and object lifecycle semantics.

## S3 vs database

Don't put a 500 MB video inside PostgreSQL just because PostgreSQL can store binary data.

Usually:

```text
PostgreSQL -> metadata
S3 -> file
```

Example:

```text
users
id | name | avatar_key

S3
users/123/avatar.jpg
```
